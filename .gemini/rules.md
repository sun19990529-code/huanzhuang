# 🛡️ 智能衣橱项目最高开发规范与规则守则 (Project Rules)

> **生效级别**：项目最高约束（Always On）。每次会话开始或恢复时必须无条件加载并严格执行。

---

## 一、 核心底线：功能防倒退与反破坏性重构

1. **【严禁因 UI/UX 改动破坏既有功能】**
   - 任何涉及样式、布局、Tailwind 类名、组件外壳的修改，**严禁擅自改动、删除或降级已经验证通过的业务逻辑、数据流与算法**。
   - 视图层（UI）必须与逻辑层（API / Store / Canvas Engine）完全解耦。
   - 修改完 UI 后，必须进行核心链路回归验证，确保：
     - 2D 大画布的自由平移、缩放、旋转、层级切换与 AI 像素级吸附依然有效；
     - 白底透明化与单品展示依然有效；
     - 3D VTON 生成依然与画布选中单品强关联。

2. **【外科手术式修改准则】**
   - 只修改必须修改的代码，严禁顺手重构未损坏的模块。
   - 每一行代码修改必须能直接追溯到用户的具体诉求。

3. **【实用主义体验优先准则】**
   - 用户的即时交互响应（1~3ms 极速反馈）与平滑无白屏秒切体验，永远凌驾于理论上的过度设计之上；
   - 严禁为了追求理论上的绝对强一致性而给轻量高频交互强行增加磁盘阻塞事务；
   - 严禁为了消除常规构建体积提示而盲目引入 `React.lazy` 懒加载，避免页面路由切换产生白屏或加载顿挫。

## 二、 资产权限、公共衣橱隔离与单品批量管理规范

1. **【严禁删除公共单品（绝对红线）】**
   - 普通用户仅允许删除自己私有上传的单品资产；
   - **【绝对红线】严禁普通用户删除公共衣橱/系统预设单品**；
   - 服务端接口（无论是单品删除 `DELETE /v1/garments/:id` 还是批量删除 `POST /v1/garments/batch-delete`）必须严格执行 `db.isGarmentOwner(userId, garmentId)` 水平越权校验，对公共单品直接拒绝（403）或批量静默跳过；
   - 前端视图层严格防护：公共单品卡片**严禁展示删除按钮与批量勾选框**；批量模式下的“全选”功能必须自动过滤排除公共单品（仅勾选 `!item.isPublic`）。

2. **【私有单品删除与批量管理链路】**
   - **单品删除防误触**：单件删除私有单品必须附带原生防误触二次确认；
   - **穿戴安全联动卸除**：当单品被删除时（单件删除或批量删除），若该单品正被穿戴在当前模特身上，**必须同步从全局 `wornItems` 状态中安全卸除**，彻底杜绝画布上残留幽灵图层或报空指针异常；
   - **接口与符号隔离**：普通用户端批量删除（`batchDeleteUserGarments`，调用 `/v1/garments/batch-delete`）与后台 CMS 管理员批量删除（`batchDeleteGarments`，调用 `/v1/cms/garments/batch-delete`）必须在 API SDK 中**采用独立的函数命名与明确的 TypeScript 返回类型**，严禁同名冲突覆盖；
   - **批量管理交互模式**：
     - 工具栏提供清晰的 `[ 批量管理 ]` / `[ 退出管理 ]` 状态切换；
     - 批量模式下，整张单品卡片点击统一映射为勾选/取消勾选，并显示红边高亮；
     - **手势防冲突守卫**：批量模式下卡片底部的“穿上试衣”按钮必须**自动置灰禁用**，严禁误触发试穿逻辑；
     - **吸底操作栏规范**：批量模式必须在底部弹出高定毛玻璃悬浮操作条，实时展示 `已选 X/N 件`，并提供 `[ 全选 / 取消全选 ]`、带已选数量统计的 `[ 批量删除 (X) ]` 二次确认按钮及 `[ 完成 ]` 退出入口。

3. **【单品 360° 档案抽屉规范】**
   - 单品卡片左上角必须常驻 `[ ⓘ ]` 详情入口，点击图片、标题或微标唤出完整 360° 档案抽屉（`GarmentDetailDrawer`）；
   - 抽屉内集中承载单品高清切片展示、多态形态切换（敞开/合拢/塞入/外放）、面料材质、版型细分、三维尺码与私有单品快捷删除功能。

## 三、 工作台交互与视觉品质守则

1. **【左侧悬浮控制坞 (Left Dock) 交互标准】**
   - **2D / 3D 分段切换**：必须具备 **硬件加速的平滑滑块胶囊动效（Sliding Pill Indicator）**，严禁生硬瞬间跳变；
   - **形态切换核心入口**：替换冗余的身材工坊（身材管理统一收敛至账号设置）；智能识别选中单品或当前穿戴的上衣/外套，支持形态切换时高亮并显示当前状态（如 `已塞入` / `已敞开`），不可切换或未穿戴时**自动变灰禁用（Disabled）**，悬浮提示 `此衣物无形态切换`；
   - **一键清空按钮**：必须**保持常驻**以保证控制坞高度稳定；无穿戴单品时自动置灰禁用。

2. **【3D 卷帘对比 (Split Curtain Slider) 标准】**
   - **全视口丝滑拖拽**：必须挂载全局 `window` 鼠标与触控事件监听，基于 3:4 模特容器真实坐标精准计算百分比，确保全屏任意位置滑动 100% 顺滑跟手；
   - **1.5px 轻奢发丝分割线**：严禁粗大白色厚条，必须使用 **`1.5px` 极细半透明白色发丝线** 与 **微型磨砂毛玻璃胶囊手柄（`w-5 h-8`）**；
   - **左右互补硬件级裁剪**：左侧 2D 拼搭层与右侧 3D 成片层必须同时绑定互补的 `clip-path` 遮罩（左侧 `inset(0 100-pos% 0 0)`，右侧 `inset(0 0 0 pos%)`），**严禁 2D 衣物或 3D 成片跨线穿透**。

3. **【2D 交互选框零穿模与全品类自适应规范】**
   - **弹窗防穿模守卫**：在呼出任何 Modal（AI 生图中、保存搭配、抽签机、海报生成等）、单品抽屉或进入 3D 模式时，必须**前置取消选中（`setSelectedItemId(null)`）**；2D 红色虚线选框、放大手柄与脱下胶囊严禁在弹窗蒙层下方/上方穿模显现；
   - **全品类按键位置自适应**：交互功能按键（旋转手柄、缩放角标、层级调整、脱下胶囊）**必须针对上装、下装、鞋履、连体裙、配饰等所有品类单品自适应贴合**，严格根据当前单品在画布上的实时 BBox（外接矩形边界与缩放比例）动态计算坐标，严禁为下装或特定单品硬编码固定位置导致按键错位或重叠；
   - **按键间距规范**：功能按键与选框外缘之间必须保持统一的缓冲间距（规范为 `12px~16px`），保证触控手势防误触且视觉精致。

4. **【2D 模特舞台几何居中规范】**
   - 3:4 模特黄金画幅在工作台视口内必须实现**绝对水平与垂直几何居中**；
   - 高度计算必须动态扣除顶部全局 Header 和底部移动端抽屉占用的实际物理高度：
     - 在 `PEEK` 模式下，按实际小抽屉高度（142px）动态扣除；
     - 在 `COLLAPSED` 全收模式下，按极简指示条高度（28px）动态扣除，使模特舞台向下延展并自适应占满整幅画布；
     - **严禁在容器类名中硬编码写死单一模式的底部间距**，彻底杜绝全收状态下底部留出 114px 的无效黑洞空白。

5. **【移动端底部抽屉 (BottomSheet) 手势与状态守则】**
   - **三阶段状态机**：移动端抽屉支持 `COLLAPSED`（全收隐藏以完全露出画布）、`PEEK`（露出单品卡片头部与抓手）、`EXPANDED`（全开大视域）三种明确状态；
   - **全收常驻悬浮唤回胶囊 (FAB)**：抽屉在 `COLLAPSED` 全收状态下，必须在右下角提供优雅的 FAB 浮动胶囊（带穿戴计数），支持一键唤回抽屉；
   - **手势触摸区物理隔离**：拖拽手势监听必须**严格限制在顶部触摸抓手（Drag Handle）区域**，严禁在下方单品滚动列表内捕获竖向滑动，彻底避免手势与列表纵向滚动产生冲突；
   - **拖拽阻尼与动画吸附**：抽屉在拖拽释放后必须具备平滑的弹性阻尼吸附动效，展开状态下不得无故阻断或默认展开复杂筛选条，确保用户交互轻量顺手。

## 四、 外网域名与网络通信规范 (`suncraft.site`)

1. **【Vite 服务器外网与 Host 放行】**
   - 前端 Vite 开发与预览配置必须绑定 `host: '0.0.0.0'` 与 `cors: true`；
   - `allowedHosts` 必须包含 `['suncraft.site', '.suncraft.site', 'localhost', '127.0.0.1']`，彻底放行外网自定义域名访问。

2. **【客户端 API / WebSocket 动态同源适配】**
   - 客户端（`web/src/api.ts`）API 与 WebSocket 根地址**严禁硬编码 `localhost:3001`**；
   - 必须通过 `window.location.host` 动态自适应（通过 `/v1` 代理透明路由），确保通过 `suncraft.site` 域名、反向代理或局域网访问时通信畅通。

3. **【后端服务监听与全域 CORS】**
   - 后端服务显式监听 `0.0.0.0:3001`；
   - CORS 必须全域动态放行所有合法域名来源、凭据携带与自定义认证头（`Authorization`, `x-auth-token`, `x-user-id` 等）。

1. **【严禁主动清空/重置数据库】**

3. **【自动化测试契约与真实数据严格对齐】**
   - 严禁在测试代码（`server/tests/`）中随机构造或硬编码假用户 ID、假单品 ID；

   - 严禁使用固定假图糊弄用户。
   - 严禁使用 Mock 假数据或伪随机算法替代真实的 AI 推理与生图。

## 七、 模特素体与服装资产规范

1. **【3:4 黄金画幅全链路贯通】**
   - 从新用户注册、身材工坊重构、2D 大画布模特展示到 3D VTON 最终试穿大片，**全链路画幅严格锁定为 3:4 黄金画幅（768×1024 / 1440×1920）**。
   - 严禁退化为 1:1、9:16 或任意非标比例。

2. **【模特素体生成规范】**
   - 模特形态必须为标准正面 A-Pose 站姿、肉色贴身素衣、纯白底；
   - **无图注册/生成**：根据用户填写的五维身材参数，生成 **20岁左右中国籍面孔** 标准 A-Pose 模特；
   - **有图注册/照片重构**：提取用户照片中的五官面容与发型，结合身材三围解剖重构为 3:4 A-Pose 模特；
   - **【绝对红线】严禁将未经 AI 重构的用户生活照原图直接存入数据库作为素体**。

3. **【服装单品平铺素图（Ghost Mannequin）规范】**
   - 用户上传单件或多件穿搭照后，AI 识别出单品属性及局部区域；
   - 必须调用 `gemini-3.1-flash-image` 为每件衣服**独立重新绘制纯白底电商幽灵平铺素图（Ghost Mannequin / Flat Lay）**；
   - **【绝对红线】严禁使用从原图中直接裁切的带有人体皮肤、脖子、肢体和生活照背景的局部切片**；
   - 必须通过 Alpha 抠图算法剔除纯白底，产出纯净透明底服装资产并在确认弹窗与衣橱中展示。

## 八、 传输性能与重复请求防范

1. **【客户端图片自适应轻量化】**
   - 上传生活照或合成 2D 拼搭快照前，客户端必须执行 1024px 尺寸规范化与 WebP/JPEG 压缩，杜绝巨型 Base64 阻塞网络或触发网关显存溢出；
2. **【防抖与重试去重】**
   - 入库流程与生图提交必须设置前端锁状态与防抖，严禁因用户重复点击或长连接重连引发二次调用重复录入；
3. **【超时阈值与异常沙箱】**
   - 生图接口超时阈值统一设置为 240s；
   - 服务端必须挂载未捕获异常守护与完善的 `try...catch` 安全沙箱，严禁服务因网络波动崩溃中断。

## 九、 全局弹窗与抽屉架构规范 (React Portal 防御与 Containing Block 隔离)

1. **【精准按需使用 React Portal，严禁无故重构】**
   - **适用场景与防御边界**：当且仅当全局抽屉或弹窗被嵌套在带有局部滚动（`overflow-y-auto`）、或含有 `transform`、`filter`、`backdrop-filter` 等会创建局部包含块（Containing Block）和局部层叠上下文的祖先节点中，且引发了**定位偏移、被截断、露缝或被兄弟元素压制**时，才必须使用 `createPortal(node, document.body)` 隔离挂载到根节点（如已修复对齐的 `GarmentDetailDrawer`）；
   - **防破坏性重构红线**：对于当前挂载层级定位正常、居中良好、遮罩层无破损的模态弹窗（如 `InstantOotdPosterModal`、`LookbookModal`、`CapsuleSlotMachine` 等），**坚决保持现有组件架构不变，严禁为了教条式规范进行盲目重构**，杜绝引入样式上下文断裂或非预期手势冲突；

2. **【移动端全宽满屏与各端对齐标准】**
   - 全局抽屉容器宽度在 Tailwind 中必须声明为 **`w-full md:max-w-md`**；
   - **移动端（`< md`）**：必须 100% 满屏无缝贴合（宽度 `w-full`，高度 `h-full`），顶部与底部贴齐视口，**严禁在移动端出现 15px 黑底遮罩漏缝或上下留白错位**，确保在“我的衣橱”和“试衣间”等所有入口打开的视觉体验 100% 像素级对齐；
   - **PC 端（`>= md`）**：保持标准的右侧悬浮滑出抽屉（`max-w-md`），配合毛玻璃背景与阴影。

3. **【DOM 树末端挂载守则】**
   - 在各视图组件（如 `WardrobeGalleryView.tsx`）中，全局抽屉与弹窗必须放置于**视图最外层根容器的末端**，与滚动主内容区保持平级，禁止嵌入任何局部列表子树中。

## 十、 移动端全屏视口与安全区规范 (100dvh 与 Safe Area)

1. **【100dvh 视口锁定】**
   - 移动端 App 顶层容器必须使用 `h-screen h-[100dvh] overflow-hidden`，严密适配 iOS Safari 和 Android 移动端浏览器地址栏伸缩，杜绝页面产生双重滚动条或意外反弹滚动。

2. **【全面屏手势条 Safe Area 适配】**
   - 底部固定导航栏（`Bottom Nav`）、悬浮操作栏（`Floating Action Bar`）和吸底按钮组必须强制绑定安全区底部内边距：
     `pb-[max(env(safe-area-inset-bottom),0.5rem)]`；
   - 严禁按钮贴死屏幕物理底部而被手机手势指示条遮挡或误触。

## 十一、 多维复合筛选与搜索架构规范 (GarmentFilterBar)

1. **【统一数据契约】**
   - 衣橱单品库（`WardrobeGalleryView`）与试衣间底部抽屉（`FittingStudioView`）必须统一使用共享组件 `<GarmentFilterBar />` 和数据结构 `GarmentFilterState`；
   - 筛选体系涵盖：多色系匹配（基于真实 HEX 颜色库及名称映射）、次级品类细分匹配、花纹图案匹配及关键词综合搜索。
